Bottleneck #1: make_gif (20.7s, 34%)
-------------------------------------
Each frame is rendered through a full matplotlib Figure (imshow + text + grid)
then savefig->PNG->imageio.imread. With --test_run stride=1 that is 10 frames
x 4 bands = 40 heavyweight renders. This is the largest single lever.
  - Fix A: bypass matplotlib entirely. zscale-normalize the array to uint8 and
    imageio.mimsave the frames directly (no Figure/savefig). ~5-10x faster.
  - Fix B: if matplotlib stays, drop dpi (80->50), reuse one Figure/AxesImage
    via set_data() instead of new fig per frame, and downsample large frames.
  - Fix C: --no_gif already exists; consider making GIF opt-IN for routine runs.

Bottleneck #2: matplotlib resample (11.0s self, inside savefig)
---------------------------------------------------------------
imshow resamples full-resolution CCD arrays to the figure raster on every plot
(ref, alignment, stacks, gif). Levers:
  - downsample image data before imshow (the figures are only a few hundred px),
  - pass interpolation="none" / interpolation_stage="data" where appropriate,
  - smaller figsize / lower dpi for diagnostic PNGs.

Bottleneck #3: run_band parallel wait (7.3s in lock.acquire)
------------------------------------------------------------
The 7.3s in _thread.lock.acquire is the main process WAITING on SequenceParallel
worker processes, not CPU work. For --test_run (only 10 frames/band) the
fork+IPC overhead is a large fraction of the band cost; for full-length runs
the parallelism pays off. Not a real bottleneck for production-size datasets.

compute_bjd_tdb dropped to 1.7s (was 10.1s in the 2026-06-11 profile) -- the
earlier cost was barycorrpy; the default astropy light-travel path is cheap
aside from a ~1s TLS handshake for the MAST object resolve.


Takeaway
--------
This pipeline is plotting-bound, not compute-bound: ~75% of wall time is
matplotlib rendering (GIF + diagnostic PNGs), ~20% is the photometry itself.
Highest-ROI optimizations, in order:
  1. Rewrite make_gif to skip matplotlib (direct uint8 frames).        ~ -15s
  2. Downsample/shrink imshow inputs in plot_* + lower diagnostic dpi.  ~ -8s
  3. Make GIF opt-in (or default --no_gif) for batch reductions.
